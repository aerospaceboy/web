把一段录屏交给 AI，最难的往往不是“生成总结”，而是让文字、画面和时间点能够相互核对。

**Video2AI** 是一个本地视频资料整理工具：把语音字幕、关键帧、可选屏幕文字和画面描述汇成时间轴，再导出离线报告与适合 Agent 接手的资料包。它保留证据入口，让后续阅读、排错和交接有据可查。

## 为什么做这个工具

教程、课程录屏和开发过程记录通常同时包含讲解、代码、界面变化与报错。只有字幕会遗漏画面，只有截图又难以追溯讲解；一次长总结也容易丢掉上下文。

这个项目把输出设计成“可回查的资料包”：先组织带时间戳的证据，再按需调用 AI 辅助阅读。重点是保存线索与出处，而不是把模型生成的判断直接当作事实。

## 从视频到证据的处理流程

1. **读取媒体与音轨**：识别视频基础信息，提取音频；无音轨时仍可继续处理视觉证据。
2. **生成语音字幕**：通过 faster-whisper 输出带时间戳的文本与 SRT 字幕。
3. **保留视觉时间点**：结合场景变化和最大截图间隔提取关键帧，并对重复画面做保守去重。
4. **按需理解画面**：源码版可开启 PaddleOCR；也可配置视觉模型，为关键帧生成画面描述。
5. **融合时间轴**：把讲解、屏幕文字和关键画面关联到相应时间段。
6. **导出与交接**：生成 Markdown、结构化时间轴、离线网页报告、联系表及精简上传包。

AI 总结和画面理解均为可选项。没有配置云端服务时，基础字幕、画面和时间轴仍是资料包的核心。

## 离线报告与 Agent 接手

离线 `report.html` 将章节导航、字幕、OCR 文字和关键帧放在同一页面，支持文字搜索。正式报告中的关键画面可以放大查看；网页引用资料包内的相对图片路径，不依赖在线报告服务。

资料包里不同文件各有用途：

| 文件或目录 | 用途 |
| --- | --- |
| `transcript.md` / `subtitle.srt` | 阅读讲解文字，并回到对应时间 |
| `timeline.md` / `timeline.json` | 按时间段整合文本和视觉线索 |
| `frames/` | 保存唯一关键帧，供人工核对 |
| `report.html` | 离线浏览章节、搜索文字和查看画面 |
| `AI_HANDOFF.md` | 向下一个 Agent 说明资料结构和阅读入口 |
| `chatgpt/upload_bundle.zip` | 汇总精简文本与画面联系表，供支持 ZIP 的目标工具读取 |

能否直接读取 ZIP、图片或长文，取决于目标 AI 工具的实际能力；也可以分别提供 Markdown 和联系表。

## 为重复处理和失败恢复做的设计

- **配置感知缓存**：源视频和各阶段参数参与指纹计算，模型、语言或视觉配置改变时重建受影响阶段。
- **按阶段恢复**：字幕、关键帧、OCR、时间轴和总结分别保存结果，避免每次从头处理。
- **失败保留基础证据**：OCR 初始化或 AI 请求失败时，尽可能保留已有字幕与画面，并允许重跑补齐。
- **目录批处理**：按文件处理文件夹内的视频；单个文件失败后继续其余文件，最后汇总结果。
- **桌面入口**：提供视频或文件夹选择、处理日志、停止、报告入口和历史资料包记录；命令行与桌面界面共用处理流水线。

Windows 便携版面向 CPU 使用，基础语音模型随包准备；源码版可以按独立环境配置使用 GPU 和 OCR。两种形式的功能与依赖有所区别，应以对应版本的说明为准。

## 本地与云端的数据边界

基础媒体处理在本机执行，工具不把原视频作为云端分析请求上传。开启云端 AI 总结后，字幕和屏幕文字会发送到配置的模型服务；开启 AI 看图后，关键帧会发送到配置的视觉服务。是否启用这些能力，应根据视频内容与所用服务决定。

密钥使用本机环境变量或单独的密钥文件配置。分享项目或资料包前，应确认没有夹带 `.env`、密钥文件、个人视频和不适合公开的识别内容。识别文字与模型描述都可能出错，技术结论需要回到原视频与画面核对。
