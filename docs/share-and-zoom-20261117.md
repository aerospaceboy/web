## 本轮新增修复

公网检查发现原 Hao Open Graph 模板将带末尾斜杠的 `site.url` 直接拼接以斜杠开头的 permalink，输出如 `https://aerospaceboy.site//archives/fpga-afdx-end-system`。同一模板的分享封面使用 `/upload/...` 相对地址。

已修正服务端 Open Graph 与 Twitter 两套标签：

- 去除站点根地址尾部斜杠，按 permalink 是否绝对地址拼接，首页仍保留一个根斜杠。
- 本站相对封面改为绝对 HTTPS 地址；协议相对图片补 HTTPS，已有绝对图片地址保留。
- 保留当前文章封面、站点头像、标题、摘要与分享卡片类型。只有封面及 Logo 都缺失时，才使用已存在的默认封面，避免输出字面量 `null`。
- 在审计中校验 `og:url`、`twitter:url` 与当前路由一致，封面为绝对 HTTPS，且两套标签封面一致。

构建入口：

```powershell
.venv/Scripts/python.exe -m blog_tools.share_metadata --backup backups/share-20261117
```

部署工具增加固定的 `--profile share`，只允许更改 `modules/common/open-graph.html`；原 metadata 配置和旧回执仍兼容。构建文件、原文件与目标路径都经过校验，原文件备份到公开主题路径外，回执保持排他创建；用错部署配置的回执会在接触 SSH 前被拒绝。

本轮私有备份/回执在 `backups/share-20261117/`，公开版本清单为 `config/share-metadata-deployment.json`。通过后台主题详情的“清理模板缓存”生效，没有重置设置、升级主题或改动正文。

回退应使用相同 `--profile share` 和该次回执；工具会校验当前文件仍与部署哈希相同，再还原原文件。还原后同样需要清理模板缓存和检查公网。主题升级前后仍须重新核对原生补丁。
