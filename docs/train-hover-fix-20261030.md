# 小火车悬停及外部跳转修复（2026-10-30）

## 已确认的原因

用户报告放大后点击小火车会卡。排查先确认它是“开往”外部随机网站入口，原链接没有 target，会替换当前标签页；实际点击进入另一家博客。这解释了外部加载占用本站标签页的行为，但不能据此断言所有卡顿都来自网络。

随后在 900 CSS 像素下测得真实布局问题：当前 Hao 主题使用 `#body-wrap:has(#travellings_button:hover) #nav #menus { display: none; }` 临时隐藏菜单，显示提示条。上一轮自适应导航计算把这个临时零宽度当成真实菜单宽度，反复切换 compact/wide，导致按钮横移 42 像素，鼠标移入/移出状态反复变化，点击可能落空。

这属于上一轮自适应代码与主题悬停提示之间的冲突，不把它归为已经证实的浏览器渲染器整体死锁。

## 修改

- `header-layout.js` 保留同一菜单最近一次非零的实际宽度。提示条临时隐藏菜单时继续使用该值；首次还没有测得有效宽度时采取收起状态，新菜单 DOM 则重新测量。恢复显示、字体和尺寸变化仍按现有观察器更新。
- `mobile-navigation.js` 只处理现有 `travellings.cn` 外链，使用原生 `target="_blank"`，保留原 href 及 rel，增加 noopener/noreferrer 和明确的无障碍名称。没有增加等待倒计时、轮询或自定义 window.open 点击处理器；Pjax 后会再次修复属性。
- 保留小火车、提示条及所有原菜单，没有修改 Halo 核心或主题包；本轮 CSS 未改。

## 验证

1. 修复前 `python -m blog_tools.check_header --train-hover --widths 900` 返回非零：悬停状态在 compact/wide 间变化，按钮位移 42px。该检查连续采样实际按钮位置与模式，能复现用户报告的交互问题。
2. 本地快照验证保持公网原 CSS/脚本顺序及页面路径，避免首页专用按钮因 `/index.html` 路径而被主题隐藏。
3. 最终公网 15 组缩小/放大切换通过；800、849、900、1100、1300 五组悬停连续采样全部通过，模式不变，按钮位移均为 0px。
4. 原生点击回归在目标标签页暂停、尚未执行外部脚本时，验证本站 URL 不变且显示模式按钮仍可执行；重复 Pjax 后链接仍为新标签页。公网紧凑布局 1000px 的同一检查也通过。浏览器内部的其他页面不计入外站新标签，只认源页创建的目标。
5. 普通浏览器实际点击创建了外部标签，原首页仍为 complete 且可读取/操作。测试外站标签已关闭，本站保留。
6. 58 项单元测试及 JS 语法检查通过；现有导航浏览器回归在加入外部跳转检查后通过。公网审计 15 页面、10 附件通过，已有隐私政策占位警告保留。

外站响应速度与可用性不受本站控制，本轮不声称加速了所有随机目标站，也不把新标签页等待时间当作本站性能基准。
