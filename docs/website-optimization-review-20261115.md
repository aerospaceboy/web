# 半截的诗：网站对标与优化建议（2026-11-15）

## 结论

值得继续优化。下一轮应围绕“让访客快速看见真实作品、判断作者能力、顺畅读完内容”推进，保留现有星空风格和可控动效。

最优先的组合是：首页精选项目、项目卡片化、窄屏文章标题区、工程文章前导信息，以及清理公开占位内容。现有 Halo 能承接这些改动，当前证据不支持为此更换建站框架。

本轮只调研和读取公开页面，未修改线上站点。

## 范围与证据

- 对标六个可访问的代表站点，包含中文功能型博客、开源作者站和工程作品集，并非穷尽全网。外站观察、来源与失败记录见 [逐站资料](website-benchmark-sources-20261115.md)。
- 本站浏览器检查首页、项目页和 FPGA 文章，读取当前 DOM，并保存桌面和窄屏截图；另外回读隐私政策、robots、sitemap、RSS 和页面元数据。
- 本站原有只读审计检查 15 个页面和 10 个既有附件，结果 `ok=true`，其中隐私政策有占位内容警告。该通过状态不代表无设计问题，也不是完整 SEO、性能或无障碍验收。
- 本站当前桌面 CSS 视口为 1348×727；窄屏检查实际 CSS 视口为 300×675。工具请求尺寸和当前浏览器缩放后的实际 CSS 尺寸不同，本报告按实际 DOM 尺寸记录，不冒称已验收 390px 或真机。
- 未获得 Search Console、真实用户性能数据、访问转化数据；未完成弱网、低端手机、全站键盘或跨浏览器验收。没有据此给各站打分或排名。

本机证据：`reports/site-review-20261115/` 和 `reports/site-research-live-audit-20261115.json`。文件在忽略目录，仅用于复查。

## 已具备的能力

当前首页有星云主视觉、樱花等氛围效果、主导航、GitHub、RSS、简历入口及站内搜索；阅读偏好提供字号、减少动效、氛围效果和打字字幕选项。两个比赛项目均已发布并在项目页提供入口；FPGA 项目已有仓库跳转。文章页已有目录、阅读设置、图注、标签和分享。

这些能力本轮已在实际页面观察，不应再次列成“缺失功能”。[首页](https://aerospaceboy.site/) · [项目页](https://aerospaceboy.site/projects) · [FPGA 文章](https://aerospaceboy.site/archives/fpga-afdx-end-system)

## 按优先级排列的建议

### 1. 完成公开页面的占位内容（优先处理）

**当前事实**：隐私政策仍显示“请在此处添加你的隐私政策内容”；首页文章中还存在“竞赛备赛流程模板”“项目记录模板”等明确的模板题目。[隐私政策](https://aerospaceboy.site/privacy-policy) · [首页](https://aerospaceboy.site/)

**建议**：按实际评论、账号、浏览器偏好和第三方资源情况填写网站说明；模板文章若确实作为教程，明确其用途，否则不放在精选展示中。这里是内容完整性建议，不宣称已完成法律合规评估。

**验收**：公开页没有默认占位指引；首页精选内容均有明确读者价值。

### 2. 首页直接展示两个代表项目（高收益）

**当前事实**：桌面首屏星云区高约 523px、底部约在 y=593；首屏主要展示品牌语与按钮，实际项目卡没有直接出现。文章区首先出现的是置顶学习路线。[首页](https://aerospaceboy.site/)

**建议**：保留星空首屏，收紧高度和信息重复，加入两张精选卡：“AFDX 双网端系统”“智巡未来”。每张只写用途、一项可核实成果、技术栈，以及详情/GitHub（有公开仓库时）入口。身份文案可更具体地说明机器人、嵌入式和 FPGA 方向，但本人职责需要由实际资料确认。

**参考**：[Anthony Fu](https://antfu.me/) 与 [idealclover](https://idealclover.top/) 把实际工作直接放入首页；[Brittany](https://brittanychiang.com/) 区分精选与完整归档。

**验收**：常见桌面宽度下，一次滚动内可见两个项目；手机不用进入菜单才能知道网站主要展示什么。

### 3. 项目页改成可比较的作品卡（高收益）

**当前事实**：项目页是标题、大图、段落逐项展开，两个真实项目之后还有五个简短的方向说明；没有卡片层面的状态、本人角色和成果字段。两个项目技术栈和文章链接已具备。[项目页](https://aerospaceboy.site/projects)

**建议**：统一横图比例，桌面两列、手机一列。字段采用“项目用途 / 我的工作 / 技术栈 / 验证范围 / 状态 / 详情与仓库”。五个方向改为轻量的能力标签区；详细介绍留在文章中。仅两个项目时，无需另加复杂搜索和筛选。

**验收**：可在同一屏比较两项作品的核心信息；状态和指标有来源，详情与仓库目标清楚。

### 4. 缩短窄屏文章标题区，并核查阅读统计（高收益）

**当前事实**：FPGA 文章在本轮 300×675 CSS 视口中，标题信息区高 600px，正文较晚出现；浅色总览图作为封面时，白色标题与元数据的对比感不稳定。该页显示 5499 和“13 分钟”，而正文 DOM 中去除空白后的可见文本约 1966 字符，两个口径明显不同。[FPGA 文章](https://aerospaceboy.site/archives/fpga-afdx-end-system)

**建议**：窄屏标题区按内容自适应，设合理高度上限；封面与文字分层或加稳定遮罩。核查 CMS 字数是否把 HTML/编辑器标记计入，统一中文字符、英文单词和阅读时长的计算口径。当前未定位统计实现，因此不把差异直接定性为某个函数错误。

**验收**：多种封面明暗情况下标题可读；常见手机宽度和 200% 缩放不遮挡关键元数据；字数由正文内容计算且说明一致。

本轮窄屏表格没有导致全页横向溢出，不能把它列为已发现的溢出 bug；后续仍应检查 360/390/768px 的文字密度和表格阅读体验。

### 5. 给工程文章增加“先读这一块”（高收益）

**当前事实**：现有比赛文章解释充分，验证边界也有说明，但开头缺少固定的快速信息块，读者需要深入正文才能提取本人职责和关键成果。[FPGA 文章](https://aerospaceboy.site/archives/fpga-afdx-end-system) · [机器人文章](https://aerospaceboy.site/archives/yzbot-lunar-warehouse)

**建议**：正文前增加 3 句摘要、适合读者、本人职责、当前阶段、最后核验日期和可公开资料入口。结果继续区分仿真、网表与实物证据。内容足够后再形成“方案—关键问题—验证—复盘”系列索引。

**参考**：[Josh 的文章前导](https://www.joshwcomeau.com/animation/css-vs-javascript/) 与 [cuteleaf 系列](https://blog.cuteleaf.cn/series/)。

**验收**：只读前导就能回答“做了什么、作者做了哪部分、证明到什么程度、去哪里继续看”。

### 6. 收拢主导航与偏好入口（中高收益）

**当前事实**：主导航包含首页、分类、标签、项目、瞬间、图库、友链、留言、文章、关于我、简历共 11 个入口，另有多枚工具图标。当前抽样未复现原先的导航重合，不能继续宣称旧问题未修复。[首页](https://aerospaceboy.site/)

**建议**：优先露出“首页 / 项目 / 文章 / 关于或简历”，其余按阅读、生活、更多组织；搜索作为明确按钮，外观偏好集中管理。保留熟悉的链接地址与键盘焦点，不用仅鼠标悬停才能发现的重要信息。

**验收**：首次访问者能快速找到项目、文章和作者信息；键盘和触屏能完成相同操作；放大后仍稳定。

### 7. 补齐搜索展示信息（中等收益）

**当前事实**：robots、sitemap、RSS 已返回 200；首页和抽样文章已有 description、OG 图。抽样的首页、项目页和 FPGA 文章 HTML 未见 `rel=canonical` 或 JSON-LD；这不是“完全没有 SEO”。[robots](https://aerospaceboy.site/robots.txt) · [sitemap](https://aerospaceboy.site/sitemap.xml) · [RSS](https://aerospaceboy.site/rss.xml)

**建议**：核查 HTTP Link 头及其他结构化数据形式后，再补稳定 canonical、`BlogPosting`/`Person` 等适用数据；首页分享图可使用与星空品牌一致的专门封面，项目页摘要人工精简。使用 Search Console 的真实索引和查询数据判断后续工作，不承诺排名。

**依据**：[Google canonical 指南](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls)、[Article 结构化数据](https://developers.google.com/search/docs/appearance/structured-data/article)。结构化数据帮助理解文章，不保证特殊展示。

### 8. 建立性能和动效预算（中等收益）

**当前事实**：已有响应式图片路径与约 202.6KB 的星云 WebP，既有动效开关也能在页面上找到；不能未经测量就说网站很慢。首页 HTML 约 216KB，抽样包含 27 个带 src 的 script 元素，这些是源码规模，不是实际耗时、总请求数或帧率。

**建议**：先测首屏 LCP、交互 INP、布局偏移 CLS，再按结果处理字体、图片、第三方组件与脚本；技术正文可默认减弱装饰，首页保留氛围，所有选择继续可控。后续交互优先做可暂停的路径回放、PID 示例或分片时序解释。

**依据**：[Web Vitals](https://web.dev/articles/vitals)、[W3C Pause/Stop/Hide](https://www.w3.org/WAI/WCAG22/Understanding/pause-stop-hide.html)。这是后续验收方向，本轮没有测得上述三项指标，也没有得出无障碍合规结论。

## 推荐实施顺序

1. 清理占位内容，完成文章统计口径和标题可读性核查。
2. 制作两个精选项目卡，调整首页与项目页层级，收拢导航。
3. 给两篇项目文章补快速信息块和明确的本人职责，积累后做系列。
4. 完成元数据、真实性能、键盘与缩放验收，再决定新增交互。

当前不优先增加音乐播放器、更多常驻粒子、自动播放背景视频、无内容支撑的新栏目或 AI 问答组件。现有两项比赛作品比新增装饰组件更值得放到访客眼前。
