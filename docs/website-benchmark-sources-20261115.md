# 个人博客与工程作品集对标资料（2026-11-15）

本文件记录外站证据，供本站审查使用。调研覆盖六个可访问的代表站点，并非遍历“全网”。未登录、留言、注册或改动任何站点。来源均为站点本身、作者自己的说明文章或该页公开加载的样式；不依据排行榜或二手推荐推断效果。

检查方式：浏览首页及相关项目/文章页，另读取部分当前页面实际引用的 CSS，确认具体断点和减弱动画规则。**未进行外站手机真机、浏览器缩放、键盘全流程、弱网、Lighthouse、帧率或耗电实测**。以下“可迁移”和“不建议照搬”是设计判断，不是外站作者结论，也不代表本站目前缺失这些能力。

## 1. 夏夜流萤 / cuteleaf：中文主题功能与内容组织

观察成功：首页、项目列表、系列列表、项目详情及图像优化文章。

- **页面事实**：主导航按文章、社交、我的、关于组织入口；外观区域提供壁纸、特效、主题色与卡片样式选项，页尾有 RSS/Atom。可借鉴的是把偏好集中在一处，避免工具图标不断挤占主导航。[首页](https://blog.cuteleaf.cn/)
- **页面事实**：项目列表提供项目搜索和状态入口，条目包含时间、技术栈、简介，并分别链接 GitHub、文档及详情。适合迁移为工程项目卡片的明确行动入口。[项目页](https://blog.cuteleaf.cn/projects/)
- **页面事实**：系列页按预定次序组织文章，显示系列文章数；它与普通标签承担不同任务。适合将一项比赛拆为“方案—调试—验证—复盘”的连续阅读路径。[系列页](https://blog.cuteleaf.cn/series/)
- **作者说明**：作者专文介绍响应式图像与 AVIF 优化，值得借鉴“展示功能也说明其性能实现”的做法；这不是本次独立测得该站更快的证据。[作者文章](https://blog.cuteleaf.cn/posts/dev-notes/astro-responsive-images-and-avif/)

**不建议照搬**：两三个项目还不必做复杂搜索、状态筛选；音乐、角色、视频壁纸与统计组件应按实际内容和资源预算选择。项目页当前仍出现“示例项目”、1970 日期，因此模板栏目存在不等于内容成熟；分析不能把它当作完善作品集的标准。[项目页](https://blog.cuteleaf.cn/projects/)

## 2. Anthony Fu：用当前重点和具体作品说明身份

观察成功：首页、项目页及当前 CSS。

- **页面事实**：首页先给短身份描述，紧接创建、维护和近期工作等实际项目链接，再导向完整项目列表。迁移重点是“访客先看见正在做什么”，而不是增加装饰性介绍。[首页](https://antfu.me/)
- **页面事实**：项目页把 Current Focus 放在大量按领域分组的项目之前，每项有一句用途说明及具体目标链接；另有 GitHub 和 Recent Releases。可借鉴“精选项目在前、完整目录在后”。[项目页](https://antfu.me/projects)
- **样式事实**：当前加载的样式中，入场效果置于 `prefers-reduced-motion:no-preference` 条件内，手绘路径等效果另有减弱动画处理。这证明存在相应规则，不代表本次逐项验证了所有效果。[当前 CSS](https://antfu.me/assets/app-ZbQ68xHX.css)

**不建议照搬**：其项目规模足以支撑许多生态分类；项目较少的网站应保留精简结构。赞助与庞大开源清单也依赖作者实际经历，不应变为个人站的必备组件。

## 3. Brittany Chiang：面向评审/招聘的精选作品与完整档案

观察成功：首页、完整项目归档；仅确认简历链接存在，未把简历中的身份信息作为本次分析内容。

- **页面事实**：主页围绕 About、Experience、Projects、Writing 展开，有显式跳过导航入口和完整简历链接，项目条目配简述、技术标签或对应图片。可迁移为“身份—能力—作品—进一步联系”的访问路径。[首页](https://brittanychiang.com/)
- **页面事实**：精选项目之外另设 All Projects，用年份、项目名和部分技术栈呈现完整清单。适合避免把所有材料都堆到首屏。[归档](https://brittanychiang.com/archive)
- **样式事实**：当前 CSS 为链接/按钮过渡以及部分对话框动画设置系统动效偏好条件，也包含响应式断点和 `focus-visible` 样式。只能据此说明设计有相应处理，不宣称完整无障碍通过。[当前 CSS](https://brittanychiang.com/_next/static/css/1205f04d95fac248.css)

**不建议照搬**：商业作品展示中的安装量、星数、用户数不能套成未经核实的个人项目指标。学生比赛项目更适合写本人职责、验证环境、可公开成果和下一步。

## 4. Josh W. Comeau：让阅读交互服务于技术解释

观察成功：首页及一篇动画技术文章。

- **页面事实**：首页文章列表提供标题、说明性副标题、摘要及继续阅读入口。摘要说明文章能回答的问题，而不只是重述技术标签。[首页](https://www.joshwcomeau.com/)
- **文章事实**：所查文章把主题分类、发布日期、更新日期、目录和 Intended audience 放在正文前段，减少读者判断内容是否适合自己的成本。[示例文章](https://www.joshwcomeau.com/animation/css-vs-javascript/)
- **文章事实**：正文用 Play 控件、可复制代码和同题对比示例解释效果。可迁移为可选播放的导航路径、PID 参数或 FPGA 时序解释；仅在演示确实增进理解时制作。[示例文章](https://www.joshwcomeau.com/animation/css-vs-javascript/)

**不建议照搬**：这是特定教学内容驱动的交互，不意味着每篇项目文章都要加入动画库。当前调研也没有给该站做性能排名。

## 5. Lee Robinson：用少量主题与更新标识建立可持续阅读

观察成功：首页及 Understanding AI。

- **页面事实**：首页区分 Notes 与 Blogs，前者围绕持续维护的主题，后者按文章列出年月。可借鉴把学习索引/长期笔记与一次性比赛复盘区分，但不必另起大量栏目。[首页](https://leerob.com/)
- **文章事实**：所查长文明确显示初始年份和更新年份，开头说明写作目的与面向的读者；正文用小节、图示和脚注关联解释及来源。[示例文章](https://leerob.com/ai)
- **设计判断**：少量稳定的入口可降低访客决策成本；这不是据页面数量或 CSS 大小推算出的转化率结论。

**不建议照搬**：不要因为结构精简就删除有用的目录或图注；阅读工具应按中文长文和工程图表的实际需要决定。

## 6. idealclover：个人主页直接承接博客与作品

观察成功：首页、作者本人关于首页设计的文章及首页当前 CSS。

- **页面事实**：主页依次露出自我介绍、分主题近期文章和个人项目，项目卡片交代用途、平台和外部目标；社交入口与联系区域独立呈现。可迁移为“精选文章 + 两个真实项目”的首页信息组合。[首页](https://idealclover.top/)
- **作者说明**：作者把设备适配、加载速度、深色模式和模块化配置列为目标，并解释多个屏幕宽度与字体子集化。这些是作者报告的设计决策，不作为本次实测成绩引用。[设计文章](https://idealclover.top/archives/643/)
- **样式事实**：当前加载的首页 CSS 仍包含 350/480/680/960 等宽度断点，说明“折叠屏/窄屏”设计有实现线索；未在对应设备上验收。[当前 CSS](https://image.idealclover.cn/projects/Homepage/_astro/index.BGCsGED2.css)

**不建议照搬**：项目上的服务人数、下载量、粉丝数属于作者自己的业务数据；不能为增强视觉效果给本站编造类似数字。也不必把所有外部平台都放到首屏。

## 可迁移设计清单（供主报告按本站实测排序）

| 设计 | 参考站点 | 建议的最小版本 | 应避免的扩大范围 |
| --- | --- | --- | --- |
| 首页精选项目 | Anthony Fu、Brittany、idealclover | 两张真实项目卡：用途、本人职责、技术栈、详情/GitHub | 为填卡片制造项目和成绩 |
| 项目浏览层次 | cuteleaf、Brittany | 精选、已完成/持续迭代等真实状态 | 项目很少就加复杂搜索面板 |
| 长文阅读前导 | Josh、Lee | 三句摘要、读者对象、最后核验日期 | 无证据的“一键 AI 总结”替代正文 |
| 连续阅读 | cuteleaf | 比赛方案、调试、验证、复盘索引 | 空的系列目录 |
| 有目的的交互 | Josh | 点击播放、带数据说明的图/演示 | 自动常驻演示占用主线程 |
| 可控动效 | antfu、Brittany | 尊重系统偏好、手动开关、键盘焦点同等可见 | 只有鼠标悬停才可发现信息 |
| 设备和资源预算 | idealclover、cuteleaf | 中文字体、响应式图、窄屏和缩放检查 | 只依赖桌面全屏截图 |

上述改进可以在现有 Halo 内容与主题结构上逐项评估；不能仅因为参照站用了 Astro/Next.js 就断言需要重建网站。
