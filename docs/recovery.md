# 备份与恢复边界

`phase5-backup-*`、`phase6-backup/` 是历史配置和内容快照，不能代替完整站点备份。它们不包含完整数据库、附件库、运行环境和全部插件主题文件。

## 后续每次上线前

1. 在 Halo 控制台使用内置备份，下载到仓库外或 `backups/`，记录时间和 Halo 版本。
2. 对下载包计算 SHA256，记录附件是否包含在该备份中，并核对当前 Halo 的备份范围说明。
3. 按实际部署方式另外保留数据库备份、附件目录或对象存储备份、容器挂载路径和环境配置、Nginx 配置及证书恢复办法。
4. 凭据与私钥独立保存，不写入 Git；不要将 `.env` 或数据库转储取消忽略后直接提交。
5. 主题、插件版本与升级前后状态应随运维记录保存。

## 验证恢复能力

在隔离环境按当前 Halo 官方流程执行恢复，逐项检查文章正文、独立页面、附件、分类标签、评论、用户登录、主题设置、RSS 和 Sitemap。记录恢复用时与遗漏内容，不能仅以压缩包可解压或 JSON 可解析作为恢复成功。

此仓库尚未保存或演练完整站点恢复，因此不承诺一键恢复。

[Halo 备份与恢复文档](https://docs.halo.run/guide/use/backup)
